Accès Git et publication du rapport

Pour Emma Henry

Une question : otmane@zineinsight.com
Pendant ma mission, ne pousse rien (git push) sans m'avoir prévenu. Mes livraisons remplacent le contenu du dépôt et effaceraient ta modification. Cloner et faire git pull : librement.

1 Installation une seule fois

  1. Installe Git for Windows (git-scm.com/download/win, options par défaut). Pour Power BI Desktop, écris-moi avant de l'installer : il faut la même version que la mienne.
  2. Crée ta clé SSH dans PowerShell, puis appuie trois fois sur Entrée (emplacement par défaut, pas de phrase secrète, confirmation). 
    ssh-keygen -t ed25519 -C "ehenry@lireka.com"
  3. Envoie-moi toute la ligne affichée par cette commande (elle commence par ssh-ed25519) : 
    Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
    Le fichier id_ed25519 sans .pub est ta clé privée : il ne quitte jamais ton poste.
  4. Dès mon feu vert, récupère le projet. emma.henry est ton compte sur le serveur, pas ton e-mail. Le dossier C:\src est volontairement hors de Documents, que OneDrive synchronise et qui abîmerait le dépôt. 
    git config --global user.name "Emma Henry"
git config --global user.email "ehenry@lireka.com"
New-Item -ItemType Directory -Force C:\src | Out-Null
cd C:\src
git clone emma.henry@20.19.33.4:C:/git/lireka.git
    Au premier clone, Git affiche l'empreinte du serveur. Réponds yes seulement si elle est exactement : 
    SHA256:eBMqTCmtpfbE5ym8v8/94o5zQl9i0h6ADtGQhMk4zJc

2 Récupérer la dernière version à tout moment

cd C:\src\lireka
git pull

Ouvre ensuite powerbi\Lireka_Profitabilite.pbip. Sans accès à la base, le rapport s'ouvre sans données : ne clique pas sur Actualiser. Si git pull refuse à cause de fichiers modifiés que tu n'as pas touchés (Desktop en réécrit à l'ouverture), lance git restore . puis recommence.

3 Modifier et publier après ma mission, ou après m'avoir prévenu

  1. Préviens l'équipe dans #analytics : une seule personne modifie le rapport à la fois.
  2. git pull, ouvre le .pbip, modifie, puis Fichier > Enregistrer.
  3. Enregistre ta modification dans Git : 
    git status
git add -A
git commit -m "Ce que tu as changé, en une phrase"
git push
  4. Dans Desktop : Accueil > Publier, espace LIREKA - Power BI, Remplacer. Ne change pas les sources de données.
  5. Dans le Service, sur le modèle Lireka_Profitabilite : Actualiser maintenant, puis Historique d'actualisation. La ligne doit indiquer Completed.
  6. Ferme Desktop, lance git restore . (la publication réécrit des fichiers), puis signale la fin dans #analytics.

4 Si ça bloque

Ne corrige rien toi-même et ne lance jamais git push --force : envoie-moi le message affiché.
Permission denied (publickey)Clé pas encore enregistrée, ou mauvais nom de compte.
Connection timed outAccès au serveur fermé de l'extérieur.
Empreinte différente de celle ci-dessusRéponds no et écris-moi.
CONFLICT ou git push refuséQuelqu'un a modifié le rapport en même temps.
