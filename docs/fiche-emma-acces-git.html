Accès Git et publication du rapport

Pour Emma Henry
Version du 30/10/2026

Le dépôt Git, hébergé sur le serveur de Lireka, contient le projet source du rapport commun. Il sert à le modifier et à le republier. Pour tes propres analyses, tu n'en as pas besoin : dans Power BI Desktop, Obtenir les données > Modèles sémantiques Power BI > Lireka_Profitabilite.
Pendant ma mission, ne pousse rien (git push) sans m'avoir prévenu : mes livraisons remplacent le contenu du dépôt et effaceraient ta modification. Cloner et récupérer les versions (git pull) : librement.

1 Mise en place une seule fois

  1. Installe Git for Windows (git-scm.com/download/win, options par défaut).
  2. Ouvre PowerShell (menu Démarrer, tape PowerShell). Crée ta clé SSH, puis appuie trois fois sur Entrée (emplacement par défaut, pas de phrase secrète, confirmation). 
    ssh-keygen -t ed25519 -C "ehenry@lireka.com"
    Si la question Overwrite (y/n)? apparaît, tu as déjà une clé : réponds n et passe à l'étape 3.
  3. Envoie-moi toute la ligne affichée, qui commence par ssh-ed25519 (Slack ou mail : elle n'est pas secrète). 
    Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
    Le fichier id_ed25519 sans .pub est ta clé privée : il ne quitte jamais ton ordinateur.
  4. Dès mon feu vert, dans PowerShell, récupère le projet. emma.henry est ton compte sur le serveur, pas ton e-mail. Le projet arrive dans un dossier lireka, dans ton dossier personnel. 
    git config --global user.name "Emma Henry"
git config --global user.email "ehenry@lireka.com"
git clone emma.henry@20.19.33.4:C:/git/lireka.git
    Au premier clone, réponds yes seulement si l'empreinte affichée est exactement : 
    SHA256:eBMqTCmtpfbE5ym8v8/94o5zQl9i0h6ADtGQhMk4zJc

2 Récupérer la dernière version à tout moment

cd lireka
git pull

Ouvre ensuite lireka\powerbi\Lireka_Profitabilite.pbip (double-clic). Il s'ouvre sans données, c'est normal : ne clique pas sur Actualiser. Si git pull refuse à cause de fichiers que tu n'as pas modifiés (Desktop en réécrit parfois), lance git restore . puis recommence.

3 Modifier et publier après ma mission, ou après m'avoir prévenu

  1. Si quelqu'un d'autre travaille aussi sur le rapport, prévenez-vous : une seule personne le modifie à la fois.
  2. git pull, ouvre le .pbip, modifie, puis Fichier > Enregistrer.
  3. Enregistre ta modification dans Git, avec une phrase qui dit ce que tu as changé : 
    git add -A
git commit -m "Nouveau graphique sur la page Marketplaces"
git push
  4. Dans Desktop : Accueil > Publier, espace LIREKA - Power BI, Remplacer. Ne change pas les sources. Le rapport reste vide jusqu'à l'actualisation : publie quand personne ne le consulte.
  5. Dans le Service, sur le modèle sémantique Lireka_Profitabilite : Actualiser maintenant. Quelques minutes plus tard, Historique d'actualisation doit indiquer Terminé (Completed).
  6. Ferme Desktop, puis lance git restore . : la publication réécrit des fichiers déjà enregistrés dans Git.

4 Si ça bloque

Ne corrige rien toi-même et ne lance jamais git push --force : envoie-moi le message affiché.

Permission denied (publickey)
Clé pas encore enregistrée sur le serveur, ou nom de compte mal écrit.
Connection timed out
Le serveur n'est pas joignable depuis ta connexion.
Empreinte différente de celle ci-dessus
Réponds no et écris-moi.
CONFLICT, ou rejected après git push
Quelqu'un a modifié le rapport en même temps.
Desktop n'ouvre pas le .pbip
Mets Power BI Desktop à jour, puis réessaie.
Nouvel ordinateur
Refais toute la mise en place : la nouvelle clé doit être enregistrée sur le serveur.
